01

The Problem — You Can't Just Compare Boxes

In classification you compare one predicted label to one true label and it either matches or it doesn't. Detection gives you no such luxury.

A detector's output is a variable-length list: each entry is a box, a class, and a confidence score. The ground truth is also a list of boxes. Two lists — of possibly different lengths — and no row that lines up with another.

You cannot write prediction == ground_truth. A predicted box at pixels (102, 88, 240, 196) and a true box at (98, 91, 244, 190) describe the same car — but they are not equal numbers. Before any score exists, two questions must be answered:

  • Which prediction belongs to which ground-truth box? Nothing in the output says so — it has to be worked out from the geometry.
  • Once paired, how good is the pairing? A box that is close but loose should not score the same as one that fits perfectly.

And some boxes pair with nothing: a prediction over empty road is a false alarm; a real object the model never boxed is a miss. Tap the toggle to see the raw output, then the matching the metric has to reconstruct:

Green = ground truth · Blue = the detector's predictions

The whole rest of this course is one long answer to those two questions — a recipe that turns two messy lists of boxes into a number between 0 and 1.

1
Key idea — Detection output and ground truth are two unaligned lists of boxes. Scoring a detector means first matching them, then grading each match.
02

IoU — Grading the Overlap

Start with the second question: given one predicted box and one true box, how well do they overlap? We need a single number — and the obvious choice is a trap.

The tempting answer is intersection: the area where the two boxes overlap. Bigger overlap, better box. But intersection is not normalized — and that breaks it completely.

▸ The trap

A box that covers the entire image fully contains every ground-truth box. Its intersection with each one is as large as possible — a perfect score by the intersection rule. Yet it is a useless detection. Intersection rewards boxes for being big, not for being right.

The fix is to divide by the union — the total area the two boxes cover together. This is Intersection over Union (IoU), also called the Jaccard index:

IoU = intersection ÷ union   ∈  [0, 1]   ·   union = area(A) + area(B) − intersection

Union grows whenever either box has area the other doesn't. So a box that is too big is punished by a large union; a box that is too small is punished by a small intersection. IoU is 1 only when the boxes are identical, 0 when they don't touch, and — because it is a ratio — it is scale-invariant: the same shapes score the same whether the object is near or far.

03

From IoU to a Verdict — TP, FP, FN

IoU is a smooth number in [0, 1]. To count how a detector did, that smooth number has to become a yes-or-no decision.

We pick an IoU threshold — say 0.5. A prediction "hits" a ground-truth box only if their IoU clears the threshold and the classes match. That turns every prediction and every GT box into one of three buckets:

  • True Positive (TP) — a prediction that correctly hits a GT box: right class, IoU ≥ threshold, and that GT not already taken.
  • False Positive (FP) — a prediction that hits nothing: it is over empty space, has too little overlap, the wrong class, or it is a duplicate of a GT another prediction already claimed.
  • False Negative (FN) — a ground-truth box that no prediction hit. A miss.

There is deliberately no "true negative". Background isn't a finite thing you can count — an image contains unlimited empty space — so detection scoring only ever uses TP, FP and FN.

The matching procedure

Matching is greedy and confidence-ordered. Sort the predictions of one class by confidence, highest first. Walk down the list; each prediction claims the highest-IoU still-unclaimed GT box of its class. If that IoU clears the threshold it is a TP and the GT is now taken; otherwise it is an FP. Any GT left unclaimed at the end is an FN. Confidence order is what decides which of two overlapping predictions gets the GT — the confident one wins, the other becomes a duplicate FP.

3
Key idea — An IoU threshold + class check sorts every box into TP, FP or FN. Matching is greedy by confidence, and the loser of two overlapping boxes becomes a duplicate FP.
04

Precision & Recall

Three counts — TP, FP, FN — collapse neatly into two ratios that measure the two different ways a detector can be wrong.

Precision — "are my detections trustworthy?"

TP ÷ (TP + FP)

Of every box the detector claimed, what fraction was real? Low precision means it cries wolf — lots of false alarms.

Recall — "did I find everything?"

TP ÷ (TP + FN)

Of every object that actually exists, what fraction did the detector find? Low recall means it misses things.

The two are in tension, and the lever between them is confidence. Every prediction carries a confidence score — and we keep only the predictions above a confidence threshold, discarding the rest before matching.

▸ Where confidence comes from

Confidence is the detector's own class score for a box — a number it emits alongside every prediction, saying how sure it is that the box is real and correctly labelled. Where that number is produced inside the network is a question for the YOLOv26 course; here we only need to know it exists. Nothing in this act is special to evaluation — we are simply thresholding output the model already gives us.

Slide the confidence threshold. Low threshold: every box is kept — recall is high, but the false alarms drag precision down. High threshold: only the surest boxes survive — precision climbs, but real objects get discarded and recall falls.

05

The Precision–Recall Curve

If no single confidence threshold tells the whole story — then don't pick one. Sweep through every threshold and record what happens.

First: one pool, not one image

Precision and recall are not computed per image. Every prediction for a class, from every image in the dataset, is poured into a single pool and sorted together by confidence. The ground-truth boxes are likewise counted across the whole dataset. The curve below describes the detector, not any one picture:

Predictions from many images are merged into one confidence-ranked list before scoring begins.

Walking down the ranked list

Sweeping the confidence threshold from high to low is the same as walking down the ranked pool one prediction at a time. After revealing each prediction, label it TP or FP at the chosen IoU threshold, then recompute:

precision = TP ÷ (TP + FP)   ·   recall = TP ÷ total ground-truth boxes

The two denominators behave differently, and that is the whole shape of the curve. Precision's denominator grows with every step — each new box, hit or miss, is one more claim. Recall's denominator is fixed — the dataset has however many objects it has. So a TP nudges recall rightward and lifts precision; an FP moves recall not at all and drops precision straight down. 06

AP and mAP — One Number at Last

A curve still isn't a score. The final step squeezes the entire PR curve into a single number: the area underneath it.

Average Precision (AP) is the area under the PR curve — a value in [0, 1]. A curve that hugs the top-right corner (high precision held all the way to high recall) encloses an area near 1; a weak detector's curve sags toward the origin.

One detail first. The raw curve is jagged, and those FP-driven dips would make the area jumpy and unfair. So before integrating, the curve is interpolated: at each recall, precision is replaced by the best precision reached at any equal-or-higher recall. This casts a monotonically non-increasing "envelope" over the zig-zag — you are not rewarded for a dip you later climbed back out of. Toggle the envelope on and off:

The "m" in mAP — mean over classes

AP is a per-class number: there is an AP for "car", another for "person", another for "bike". mean Average Precision (mAP) is simply their average. That is all the "m" means — mean across the classes:

Each class gets its own PR curve and its own AP; mAP is the mean. A class the detector handles poorly drags the whole score down.
6
Key idea — AP is the area under one class's interpolated PR curve. mAP averages AP across all classes — one number for the whole detector.
07

mAP@0.5 and mAP@0.5:0.95

One number is still hiding a choice. Back in Act 3 the IoU threshold — 0.5 — was picked by hand. Different thresholds ask for different strictness.

Every TP/FP label, and therefore every PR curve and every AP, depends on that IoU threshold. Name it explicitly and you get a family of metrics:

  • mAP@0.5 (also written mAP50) — AP computed with the IoU threshold at 0.5. Lenient: a box only roughly on the object still counts as a hit. It measures "did you find the thing?"
  • mAP@0.5:0.95 (mAP50-95) — the IoU threshold is swept over ten values: 0.50, 0.55, …, 0.95. AP is computed at each, and the ten are averaged. Strict: it also measures "how tightly?" This is the primary COCO metric, and the headline number modern detectors report.

As the IoU threshold rises, loosely-fitting boxes that passed at 0.5 fail — TPs flip to FPs, recall caps lower, and AP drops. Drag the threshold and watch AP fall; the bar chart holds all ten AP values, and their mean is mAP@0.5:0.95:

▸ Why the gap matters

A detector can post a high mAP@0.5 and a much lower mAP@0.5:0.95. That gap is a diagnosis: it finds the objects but its boxes are loose. Two models with equal mAP50 are not equal — the one with the higher mAP50-95 localizes more tightly.

7
Key idea — The IoU threshold sets strictness. mAP@0.5 rewards finding objects; mAP@0.5:0.95 averages ten thresholds and also rewards fitting them tightly.

Two thresholds, do not confuse them

IoU threshold

Decides if a matched box is tight enough to be a TP. Sweeping it gives mAP@0.5 vs mAP@0.5:0.95.

Confidence threshold

Decides which predictions are kept at all. Sweeping it traces out the whole precision–recall curve.
